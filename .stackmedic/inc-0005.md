# StackMedic Fix Notes: INC-0005

**Fix Type:** CODE
**Service:** BackgroundWorker
**Severity:** CRITICAL

## Root Cause
Concurrent writes to the payment persistence layer allow a second payment record to be persisted for the same orderId before the first is committed, causing duplicate records due to missing idempotency checks.

## Recommended Fix
Add an idempotency check in the PaymentProcessor service to verify that a record already exists for the given orderId before persisting; if it exists, skip the write. Also ensure transaction commits are atomic and include null checks on orderId fields.

## Reason
The duplicate records stem from a race condition in the payment processing code; adding idempotency logic will prevent persisting a second record when one already exists, resolving the DUPLICATE_PAYMENT_RECORD errors.
