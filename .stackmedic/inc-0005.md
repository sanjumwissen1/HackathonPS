# StackMedic Fix Notes: INC-0005

**Fix Type:** WORKFLOW
**Service:** OrderService
**Severity:** CRITICAL

## Root Cause
Reservation service failed to finalize, causing the OrderService to commit the order prematurely while the inventory hold (inv) was still incomplete. This race condition leaves orders in a CREATED state with an ORDER_UNCOMMITTED or INCONSISTENT_STATE error.

## Recommended Fix
Add retry logic in OrderService to recheck reservation status after commit and roll back the order if the reservation fails, preventing premature commitment.

## Reason
This will ensure orders are only committed when the reservation is fully resolved, eliminating the ORDER_UNCOMMITTED and INCONSISTENT_STATE errors.
