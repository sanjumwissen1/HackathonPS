# StackMedic Fix Notes: INC-0004

**Fix Type:** CONFIG
**Service:** BackgroundWorker
**Severity:** HIGH

## Root Cause
The BackgroundWorker service experienced performance degradation due to a saturated DB connection pool (9/10 connections in use) causing slow queries on the orders table, combined with thread‑pool saturation (6/8 active threads) and an expanding retry queue. Memory pressure at 84% heap usage increased GC latency, further degrading response times.

## Recommended Fix
1. Edit application.yml to set background_worker.max_threads=12.<br>2. Increase db_pool.max_size from 10 to 15.<br>3. Raise retry_queue.max_depth from 30 to 60.

## Reason
Adjusting the configuration values will provide more threads and DB connections, reducing queue buildup and query wait times, which directly addresses the observed latency spikes.
