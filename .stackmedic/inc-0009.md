# StackMedic Fix Notes: INC-0009

**Fix Type:** CODE
**Service:** OrderService
**Severity:** CRITICAL

## Root Cause
The OrderService creates an order and attempts a reservation (inventory check). When the reservation fails due to inventory unavailability, the service does not transition the order out of the CREATED state; it remains stuck in CREATED with the message 'inv phase may not have completed', causing CREATE_STATE_TIMEOUT errors.

## Recommended Fix
Add proper handling of reservation failure in OrderService: if reservation fails, set order state to CANCELLED or RESERVED with fallback logic and remove the timeout; ensure the state transition occurs regardless of inventory outcome.

## Reason
The current code does not update the order state when reservation fails, leaving it in CREATED. Implementing explicit state handling will resolve the timeout and prevent stuck orders.
