# StackMedic Fix Notes: INC-0009

**Fix Type:** CODE
**Service:** OrderService
**Severity:** CRITICAL

## Root Cause
A race condition occurs between the order commit and the inventory hold/reservation finalization. The OrderService marks an order as committed but the reservation is still incomplete, causing ORDER_UNCOMMITTED and INCONSISTENT_STATE errors. This leads to orders remaining in CREATED state with timeout warnings.

## Recommended Fix
Add null check for reservation status before proceeding to payment and increase the inv phase timeout to allow race conditions to resolve.

## Reason
The added null guard prevents the service from advancing an order when the reservation is not finalized, eliminating the inconsistent state. Extending the inv phase timeout gives more time for the race condition to clear.
