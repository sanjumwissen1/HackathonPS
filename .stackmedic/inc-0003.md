# StackMedic Fix Notes: INC-0003

**Fix Type:** CODE
**Service:** InventoryService
**Severity:** MEDIUM

## Root Cause
The InventoryService is experiencing reservation leakage due to a lack of an automatic cleanup mechanism for expired or abandoned reservations. When a user places items in a cart but fails to complete the purchase, or if a transaction times out after reserving inventory but before committing the sale, the reserved stock count remains elevated indefinitely. This accumulation of stale reservations artificially inflates the 'reserved' quantity, causing the system to continuously report a HIGH_RESERVATION_RATIO.

## Recommended Fix
Implement a scheduled background job within the InventoryService responsible for managing Time-To-Live (TTL) reservations. This job must execute periodically (e.g., every 15 minutes). The job should query the reservation data store for all records that are older than a defined threshold (e.g., 60 minutes) and automatically release these stale reservations, decrementing the reserved stock count accordingly.

## Reason
Adding an explicit cleanup mechanism directly addresses the root cause of reservation leakage by ensuring that inventory is only marked as 'reserved' for active, time-bound transactions. This will stabilize the reported reservation ratio and eliminate false positive alerts.
